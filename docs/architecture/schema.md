# Corvus — PostgreSQL Schema Reference

## Overview

The Corvus data model is built around five core tables. All IDs are UUID v4
generated by PostgreSQL (`gen_random_uuid()`). All timestamps are
`TIMESTAMPTZ` stored in UTC. All mutable tables carry `created_at` and
`updated_at`, with `updated_at` maintained automatically by trigger.

```
clients ──────────┬──── api_keys
                  ├──── resources
                  └──── policy_attachments ──── policies
                              ↑
                          audit_log (client_id FK, nullable)
```

---

## Tables

### `schema_migrations`

Tracks applied migrations for the built-in migration runner.

| Column       | Type        | Notes                    |
|--------------|-------------|--------------------------|
| version      | BIGINT PK   | Sequential migration ID  |
| name         | TEXT        | Human-readable filename  |
| applied_at   | TIMESTAMPTZ | Automatically set        |

---

### `clients`

A client is any entity that authenticates with Corvus - a service, a user,
or an external system. JWT subjects and API key owners are both clients.

| Column      | Type        | Notes                         |
|-------------|-------------|-------------------------------|
| id          | UUID PK     | `gen_random_uuid()`           |
| name        | TEXT UNIQUE | Human-readable identifier     |
| description | TEXT        | Optional                      |
| is_active   | BOOLEAN     | Soft delete / suspend         |
| created_at  | TIMESTAMPTZ |                               |
| updated_at  | TIMESTAMPTZ | Maintained by trigger         |

---

### `api_keys`

Stores SHA-256 hashes of API keys (raw keys are never persisted). Mirrors the
Redis hash at `corvus:apikeys:<hash>` - Postgres is the durable source of
truth, Redis is the fast lookup cache.

| Column      | Type        | Notes                                     |
|-------------|-------------|-------------------------------------------|
| id          | UUID PK     |                                           |
| client_id   | UUID FK     | → `clients.id` CASCADE DELETE             |
| key_hash    | TEXT UNIQUE | SHA-256 hex of the raw key                |
| scopes      | TEXT        | Space-separated scope list                |
| description | TEXT        | Optional label                            |
| expires_at  | TIMESTAMPTZ | NULL = never expires                      |
| is_active   | BOOLEAN     | Soft revocation                           |
| created_at  | TIMESTAMPTZ |                                           |
| updated_at  | TIMESTAMPTZ | Maintained by trigger                     |

---

### `resources`

A resource is any managed infrastructure object. The `kind` field is an
extensible type tag - Epic 4 (Resource Manager) will define the initial set.

| Column     | Type    | Notes                                              |
|------------|---------|----------------------------------------------------|
| id         | UUID PK |                                                    |
| client_id  | UUID FK | → `clients.id` CASCADE DELETE                      |
| kind       | TEXT    | e.g. `server`, `database`, `network`               |
| name       | TEXT    | Unique per client                                  |
| status     | TEXT    | `unknown` \| `provisioning` \| `active` \| `degraded` \| `deprovisioning` \| `deleted` |
| metadata   | JSONB   | Arbitrary key-value attributes                     |
| created_at | TIMESTAMPTZ |                                               |
| updated_at | TIMESTAMPTZ | Maintained by trigger                         |

---

### `policies`

Named rule sets that can be attached to clients or resources. Rule structure
is intentionally flexible - Epic 7 (Policy Engine) defines the rule schema.

| Column      | Type    | Notes                          |
|-------------|---------|--------------------------------|
| id          | UUID PK |                                |
| name        | TEXT UNIQUE |                            |
| description | TEXT    | Optional                       |
| rules       | JSONB   | Array of rule objects          |
| is_active   | BOOLEAN |                                |
| created_at  | TIMESTAMPTZ |                            |
| updated_at  | TIMESTAMPTZ | Maintained by trigger      |

---

### `policy_attachments`

Many-to-many join between policies and their targets (clients or resources).

| Column      | Type    | Notes                              |
|-------------|---------|------------------------------------|
| id          | UUID PK |                                    |
| policy_id   | UUID FK | → `policies.id` CASCADE DELETE     |
| target_type | TEXT    | `client` or `resource`             |
| target_id   | UUID    | ID of the client or resource       |
| created_at  | TIMESTAMPTZ |                                |

---

### `audit_log`

Append-only record of all mutating API operations. Will be converted to a
TimescaleDB hypertable (partitioned by `occurred_at`) in migration 0002
once the TimescaleDB extension is enabled.

| Column        | Type       | Notes                                   |
|---------------|------------|-----------------------------------------|
| id            | UUID       | Part of composite PK with occurred_at   |
| occurred_at   | TIMESTAMPTZ | Part of composite PK; partition key    |
| client_id     | UUID FK    | Nullable - set NULL on client delete    |
| actor_subject | TEXT       | JWT `sub` or API key `client_id`        |
| request_id    | TEXT       | Correlates with `X-Request-ID` header   |
| method        | TEXT       | HTTP method                             |
| path          | TEXT       | Request path                            |
| status_code   | SMALLINT   | HTTP response code                      |
| duration_ms   | INTEGER    | Response time in milliseconds           |
| resource_kind | TEXT       | Affected resource kind (if any)         |
| resource_id   | UUID       | Affected resource ID (if any)           |
| error_code    | TEXT       | `ErrorCode` string on error responses   |
| metadata      | JSONB      | Additional structured context           |

---

## Design decisions

**UUIDs over serial IDs** - avoids enumeration attacks and works naturally
across sharded or replicated deployments.

**JSONB for metadata and rules** - allows domain-specific attributes to be
added without schema migrations. GIN-indexed for fast containment queries.

**Soft deletes via `is_active`** - clients and API keys are never hard-deleted
to preserve audit log integrity (`client_id` FK is `SET NULL` on delete).

**`audit_log` composite PK `(id, occurred_at)`** - required for TimescaleDB
hypertable conversion. TimescaleDB demands the partition key be part of
the primary key.

**Trigger-maintained `updated_at`** - single `set_updated_at()` function
reused across all mutable tables, applied at the database level so it fires
regardless of the update source.
